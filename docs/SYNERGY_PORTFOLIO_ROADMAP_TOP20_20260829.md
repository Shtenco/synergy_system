# SYNERGY Portfolio Roadmap — Top 20 Senior Steps

**As of:** 2026-08-29  
**Scope:** all 42 repositories in the authenticated `Shtenco` inventory.  
**Goal:** converge the federation into evidence-backed, revenue-capable products without deleting historical R&D or granting AI hidden financial/payment/deployment authority.

## Portfolio objective

```text
external customer value
  -> external revenue / realized external P&L
  -> verified settlement
  -> canonical accounting / HardNAV
  -> safe reinvestment
  -> stronger products and distribution
```

Internal mint, burn, own-token revaluation, LP marks and flash-loan principal remain excluded from external profit.

## Top 20

### 1. Federation v2 + portfolio control plane — CRITICAL
Create one machine-readable registry for all 42 repositories: owner, authority, maturity, lifecycle class, next milestone and roadmap mapping. Portfolio drift becomes a CI-visible failure.

**Exit:** 42/42 registered; zero ambiguous authority owners.

### 2. Finish Economic OS convergence and hardening — CRITICAL
Close structural gaps in the canonical economic spine: strict schemas, exact field sets, unknown-field rejection, digest pinning, additive release lineage and fail-closed promotion gates.

**Repos:** `synergy_system`, `synergy_financial_os`, `ai_financial_system`, `usds`.

### 3. Capture one real External Value -> Next Capacity cycle — CRITICAL
Use one real provider settlement across the exact 12-phase Economic OS lifecycle. Provider evidence must be independently verified; synthetic fixtures never count as live proof.

**Repos:** `synergy_financial_os`, `synergy_pay_system`, `synergy_system`.

### 4. Run a real persistent 3-host Economic Testnet — CRITICAL
Deploy the checkpoint stack to three distinct persistent external hosts with durable state, fresh-process restart recovery and non-loopback propagation evidence.

**Repos:** `synergy_ai_blockchain`, `synergy_meta_os`.

### 5. Standardize cross-repo identity/evidence/event contracts — CRITICAL
Adopt one versioned envelope carrying schema generation, artifact digest, source, authority, environment, event time and evidence status across canonical domains and clients.

**Repos:** architecture, finance, payment, blockchain, network, Meta-OS, NEXUS, MIDAS, apps, engineering domains.

### 6. Apply a portfolio-wide engineering/security baseline — HIGH
Every active repo gets an explicit CI/release/security posture: dependency lock where appropriate, secret policy, build identity, SBOM/release manifest target, ownership metadata and reproducibility status. Legacy repos are frozen explicitly rather than silently treated as current.

**Scope:** all 42 repositories.

### 7. Turn MetaPay into a revenue-capable integration layer — CRITICAL
Integrate one contracted provider corridor end-to-end: KYB/AML, authenticated quotes, balance/readiness evidence, settlement, reconciliation, incident controls and fee accounting.

**Exit KPI:** first real TPV, net take rate, settlement success rate and reconciliation error rate.

### 8. Productize Financial OS as an enterprise service — CRITICAL
Expose ledger/NAV/liquidity/capacity/project APIs, durable storage, migrations, audit export, tenant/role model and reference deployment. Human/multisig authority remains external to AI.

**Repos:** `synergy_financial_os`, `synergy_matrix_sota`, `synergy_eurasian`.

### 9. Commercialize Growth OS — HIGH
Convert `synergychain` into a multi-tenant SaaS with identity, subscriptions, CRM/SMM/Sales/CFO modules, usage metering and audit integration.

**Exit KPI:** paying tenants, activation, retention, ARR and gross margin.

### 10. Ship one coherent consumer Finance/Super-App product — HIGH
Use `synergy_app` as canonical store release; integrate backend/auth/portfolio/household finance/payments/read-only trust. Keep `sinergy-super-app` as the node-capable experimental client until proven.

**Exit KPI:** store release, crash-free sessions, MAU, paid conversion and payment attach rate.

### 11. Canonicalize NEXUS with frozen benchmarks — CRITICAL
Inventory `agi_olga`, reproduce strongest generations, freeze datasets/splits, run Russian language/logic/ARC/graph/cybernetic benchmarks, then promote only reproduced components into `agi_nexus`.

### 12. Deploy AUTOPILOT as a bounded business agent — HIGH
Move `agi_autopilot` from preproduction evidence to a persistent sandbox with explicit capabilities, human approval for external actions, audit journal and zero monetary authority.

### 13. Consolidate MIDAS into one auditable investment sleeve — CRITICAL
Rebenchmark every trading lineage under one data/cost contract with OOF/walk-forward/shadow reconciliation. Winners migrate into `midas_ai`; losers remain immutable provenance.

**Repos:** `midas_ai`, `midas_ai_trading_system`, `midas_lite`, `ai_trade_terminal`, `algotrading_graph_system`, `quantum-trading_metatrader5`, `computer_vision_trading_metatrader_5`, `swap_arbitrage_metatrader_5`, `cross_forex_arbitrage_trading_metatrader_5`, `global_liquidity_dataminer`, `3D_bars_market_structure`, `multi_threaded_trading_robot_with_machine_learning_python`, relevant `ai_financial_system` strategies.

### 14. Benchmark and integrate SynergyNet + compression — HIGH
Build a 3–10 node transport testbed against matched TCP/HTTP and QUIC baselines. Select `ai_compress`/`qr_compress` codecs by total cost: bytes, CPU, latency, memory and cache effects, not archive ratio alone.

### 15. Prove one complete persistent SYNERGY node — CRITICAL
Run Meta-OS on one persistent host with SynergyNet, NEXUS and read-only control plane; prove capability separation, update/rollback and denial of disabled financial/blockchain roles.

### 16. Close TURBO host/VM proof — HIGH
Finish exact VM-entry/guest-boot evidence, virtio path, stable host profile and matched benchmark evidence before broad Windows/Android expansion.

### 17. Advance PQ blockchain to an externally operated testnet — HIGH
After the three-host deployment, add signed node identities, explicit consensus/finality specification, state sync, upgrade policy and independent security review before any production claim.

### 18. Create the first public-sector Blockchain Budget pilot — HIGH
Backfill real public Treasury/EIS data, deploy trace API/dashboard, quantify trace coverage and ambiguity/conflict rates, and package an auditable pilot proposal.

### 19. Build a federation evidence/engineering platform — HIGH
Combine `ai_language`, `ai_coder`, `nexus_science_agent`, `ai_compress` and `qr_compress` into reusable requirement trace, change evidence, benchmark provenance and scientific evidence services.

### 20. Rationalize the portfolio without destroying provenance — HIGH
Every repo becomes explicitly `CANONICAL`, `PRODUCT`, `R&D`, `LEGACY`, `PRESENTATION` or `PLACEHOLDER`. Redirect duplicates, freeze obsolete branches, preserve negative results, and expose current status/benchmarks on public investor/technical surfaces.
